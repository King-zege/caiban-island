# 采办岛当前设计系统

视觉方向是“精密采购工作台”：安静、可核对、下一动作优先。借鉴 Dynamic Island 的信息层级和连续变化，不复制 macOS/iPhone 外观。实际 token 以 `src/shared/designTokens.ts` 为唯一来源，本文只定义语义与使用规则。

## 1. 核心原则

1. L1 只提供入口；L2 回答“下一步做什么”；L3 一次处理一个任务或工作区。
2. 采购项目、合同、杂事和 Agent 语义分明，不用同一种卡片承载所有内容。
3. Acrylic 只属于外壳；内容靠留白、分隔和稳定网格建立层级，禁止无意义卡片套卡片。
4. 状态不得只依赖颜色；悬停不抢焦点，自动收起、返回和全屏退让可预测。
5. 安全后果可见：外部目标展示真实地址，凭据默认遮罩，Agent 写入显示权限或差异确认。

## 2. Token 规则

- 字体：Segoe UI Variable → Microsoft YaHei UI → Segoe UI → system-ui；时间/路径可用 Cascadia Mono → Consolas。
- 字号层级：Display 28/34、Headline 24、Title 18–20、Body 14/20、Label/Utility 11–12。Windows 文本缩放时允许增高和滚动，不缩小字号。
- 间距只用 4/8/12/16/20/24/32px；交互目标至少 44×44px，相邻目标至少 8px。
- 圆角：L1/Chip 999px、L2 32px、L3 24px、Section 16px、Control 12px。嵌套遵循外大内小。
- 边框通常 1px；键盘焦点环 2px、外偏移 2px。
- 冰蓝是唯一主交互强调。完成绿、进行中蓝、待完成黄、取消灰、紧急红/高优先橙只用于小图标、文字、2–4px 轨迹或描边，禁止大面积状态底色。
- 高对比度使用系统颜色；深浅主题都必须满足正文 WCAG AA。弱提示色不得承载关键状态。

## 3. 窗口与布局

### L1

- 视觉条 96×6 逻辑像素，仅底部 4–6px 进入工作区；顶部一侧平直、下侧胶囊。
- 无文字、计数或 Acrylic；触发热区约 120×10，不能吞掉下层点击。

### L2

- 宽 760px；高度由存在的采购项目、合同、杂事轨道累计，单轨约 196–280px、双轨 376px、三轨与 Agent 封顶 480px；屏幕不足时限高滚动。
- 顶部固定“任务卡片 / Agent”，默认任务卡片。工具行高 52px。
- 项目凭条约 248px 宽、合同卡约 232px 宽、杂事工作单约 216×88px；三条轨道各自横向虚拟化，实际渲染卡片不超过 7。
- 项目凭条顺序：任务名 → 下一节点 → 风险/deadline/紧急度 → 节点轴。卡片主体、紧急度、节点和更多菜单必须是分离的可访问控件。
- 杂事只显示名称与提醒状态，正文进入 L3，独立完成按钮立即归档。
- 合同卡使用细轨迹区分履约风险，固定显示简称、状态/合同号、供应商、下一履约动作与时间；简称最多两行，不在 L2 展示被截断的正式全名。
- Agent 权限条紧凑展示主工作目录名称、来源数、可检索数和扫描状态；选择/更换与刷新索引留在现有 Agent 设置区，不新增 L2 导航入口。
- Agent 以消息轨道为主体，输入区固定可见；会话、权限、运行阶段、工具状态、错误重试和待确认项不得因 compact 布局消失。

### L3

- 最大为主屏工作区 85%，约 240px 左侧导航 + `minmax(0, 1fr)` 主区，主要阅读宽度不超过 960px。
- 左侧按采购项目 → 合同 → 杂事分组，并同时搜索正式全名、简称、合同号与供应商。
- 项目一次显示概览/节点/资料/提醒/备注之一；合同一次显示概览/履约/付款开票/验收/资料/备注之一；杂事使用无页签单页。
- Agent、记忆、归档、设置为次级工作区；L3 无独立“AI 草稿”。设置分常用、Agent、飞书同步、数据与高级。
- L2/L3 共用 AgentWorkspace；只允许密度不同。从 L3 返回一律回到 L2 任务卡片。
- 760px 以下隐藏侧栏并使用顶部选择器；内容改单列，标签可横向滚动但不得压缩命中区域。

## 4. 组件与状态

- **Button/Input**：12px 圆角、44px 高；Primary 只用于当前最主要动作；Danger 不使用大面积红底。
- **Menu/Dialog**：使用不透底的 fallback/overlay 面，锁定焦点并在关闭后恢复；空、加载、失败和重试状态不与正文重叠。
- **Task card**：常驻内容依赖细边与表面层级，不加独立大阴影；长标题必须 `min-width: 0` 并明确省略。
- **Node trail**：状态同时用图标、线型、文字和少量颜色；状态必须显式选择，禁止点击循环。
- **Approval**：紧邻相关 Agent 消息，显示风险、旧值→新值和批准/拒绝；批准后说明继续当前循环。Bypass 始终显示警示。
- **Toast/Async state**：成功、失败、后台继续和重试均有文本反馈；live region 不播报敏感正文。

## 5. 动效

- 跨层级每次最多一次原生 resize。composited 使用约 200ms transform/opacity/radius；software 使用约 120ms 淡入淡出；direct 单帧切换。
- 过渡期间控件不可交互，使用纯色 fallback；完成后恢复 backdrop 与焦点。
- 层内状态变化约 160ms；不使用常驻呼吸、无业务意义视差或宽高连续动画。
- 高对比度、减少动画或 GPU 异常时关闭 Acrylic 和补间，直接到最终状态。

## 6. 输入与无障碍

- 卡片支持方向键、Home/End、Enter；菜单支持方向键、Home/End、Enter/Space、Esc；Dialog 保持焦点并恢复触发按钮。
- 拖动、菜单、按钮和进入 L3 的点击必须隔离，避免一次输入触发两个动作。
- 所有核心流程支持键盘与读屏；`aria-current`、`aria-checked`、`aria-pressed`、live region 与可见文字按语义使用。
- 验证深色、浅色、高对比度、减少动画、100/125/150% DPI、200% 文本、长中文和 0/1/7/100 任务。
