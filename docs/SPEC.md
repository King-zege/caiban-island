# 采办岛当前产品规格

当前稳定版为 `v0.4.0`。平台为 Windows 10 1809+/Windows 11 x64，单机、单用户、本地优先，免安装 portable 分发。

## 1. 产品边界

采办岛是常驻主显示器顶部的采购全流程与合同生命周期工具。用户应能在几秒内确认最重要的采购节点、合同履约事项、杂事和下一动作，并在同一窗口中完成编辑、Agent 对话、提醒、归档与导出。

- 正式数据以本地 SQLite 为准；飞书多维表格只允许本地向外单向同步。飞书机器人只作为受控 Agent 输入/审批通道，不能直接读写数据库。
- 手动创建和编辑始终可用，不依赖模型 Provider、网络或本地 CLI。
- 采购项目、合同与杂事是三条工作轨道；采购项目与杂事创建后不可互转，一个采购项目可关联多份合同，合同也可独立录入。
- Agent 是应用的原生操作接口，所有正式操作受 AppCommand 与权限边界约束。

## 2. 三级窗口

### L1 隐藏条

- 主屏顶部中央，视觉条 96×6 逻辑像素，仅露约 4–6px；不显示文字，不拦截下层点击。
- 顶部中央约 120×10 热区停留 250ms 后展开；使用屏幕坐标检测，不使用透明覆盖窗口。
- 真正全屏应用出现时隐藏，离开全屏后恢复；普通最大化不算全屏。

### L2 快速工作区

- 默认宽 760px；按实际存在的采购、合同、杂事轨道增高，三轨封顶 480px，Agent 为 480px。窗口切换一次只提交一次原生 resize。
- 首次进入默认“任务卡片”，顶部可切换“Agent”。鼠标离开且无交互 400ms 后回到 L1。
- 项目以横向采购凭条展示；合同卡显示简称、合同号、供应商、金额、扫描件摘要、下一节点和风险；杂事以独立低矮工作单展示。列表支持鼠标、触摸、滚轮、方向键、Home/End 与吸附。
- 卡片主体、紧急度、节点和更多菜单是分离控件。菜单打开、编辑、拖动或对话框期间暂停自动收起。
- L2 Agent 只保留消息轨道、思考/工具/审批状态与输入区；权限选择、目录、自动化、会话管理、导出和删除只在 L3 操作。收起或隐藏时继续运行，展开至 L3 时保持同一会话、流文本、权限、工具和待确认项。

### L3 深度工作台

- 最大为主屏工作区 85%；左侧约 240px 任务/工作区导航，右侧只显示一个主工作区。
- 项目包含概览、节点、资料、提醒、备注；合同包含概览、合同节点、付款开票、验收、资料、备注；杂事使用无页签单页。
- Agent、记忆、归档和设置作为次级工作区；不再提供独立“AI 草稿”。
- L2/L3 使用同一个 Agent store 与消息组件；L2 是纯对话视图，L3 承载完整管理控件。从 L3 返回或按 Esc 一律进入 L2 任务卡片。
- L3 不因鼠标离开自动收起；退出应用只能通过托盘。

## 3. 任务模型与业务规则

### 采购项目

- 必填正式全名与卡片简称；正式全名用于 L3、搜索、Agent、导出和文件匹配，简称用于 L2。正式全名 1–500 个字素，简称 1–24 个字素且卡片最多两行。
- 字段：说明、采购方式、流程模板版本、紧急度（紧急/高/普通/低）、可选 deadline、时区、节点、项目提前量提醒、链接、Markdown 备注。
- 内置流程覆盖申请受理、立项/策略、寻源、采购文件/邀约、截标、开标、评审定标、结果通知、合同起草和签署；项目保存模板版本，节点标记模板/Agent/自定义来源，后续模板升级不静默修改既有项目。
- 节点字段：标题、说明、可选开始时间、可选截止时间、状态与稳定顺序。开始时间是准时提醒；截止时间仅用于计划。
- 节点状态为待完成、进行中、已完成、已取消。进度 = 已完成 / 有效节点；取消节点不进入分母或下一动作。

### 杂事

- 字段：名称、可选精确提醒时间、时区、链接、Markdown 备注。
- 不显示或接受紧急度、deadline、节点和项目进度。旧版 deadline 只允许用户转换为未来精确提醒或清除，不自动通知。

### 合同

- 信息不完整时允许先创建草拟合同卡；正式全名与卡片简称至少填写一项，缺少的一项由 main 可靠派生。合同号、供应商、整数最小货币单位金额、币种、扫描件、附件、附属链接、关联采购项目、签署/生效/到期日期和时区均可稍后补充。
- 状态为草拟、履约中、收尾、已关闭、已终止或已归档；状态变化使用独立生命周期命令，普通台账编辑不得绕过状态机。
- 合同可连续建立多个节点，支持付款、开票、交付、验收、续签、到期、归档和自定义事项并按稳定顺序保存；开票节点可关联付款节点。节点状态为待完成、进行中、已完成或已豁免。
- 每个合同节点可独立设置计划完成时间和精确提醒。节点完成/豁免或合同关闭/终止/归档后停止提醒；恢复时只重建未来提醒。
- 合同资料分为本机文件附件与 http/https 附属链接。文件记录必须是本机磁盘绝对路径，拒绝相对、UNC 和设备路径；应用不复制或上传原文件，打开前展示完整目标并要求确认。首个文件作为卡片及概览的扫描件摘要。

### 主工作目录与知识检索

- 已授权本地绝对路径中至多一个标记为主工作目录；拒绝 UNC、设备路径、路径逃逸及越界符号链接/目录联接。
- 首次设置后创建不覆盖的“采办岛 Agent”人类可读目录，并在后台扫描；顶层目录只形成项目候选，正式绑定采购项目必须经 AppCommand 和当前 Agent 权限。
- PDF、DOCX、XLSX、PPTX、Markdown、TXT、CSV 提取正文并保留页码、工作表、幻灯片、段落或行定位。旧式 Office、压缩包、图片及无文本扫描 PDF 只索引元数据并说明不可提取。
- 索引使用相对路径、大小、修改时间及 SHA-256 内容指纹增量更新；监听与启动校对结合，扫描可取消、并发有界，删除同步移除来源和分块。
- 正文始终视为不可信资料，不是 Agent 指令；检索返回前扫描提示注入、凭据和敏感绝对路径，正文不进入日志、通知或 Agent 事件。

### Agent 自动化与每日工作清单

- 首次启用主工作目录时创建“每日工作清单”自动化，使用系统本地时区每天 09:00 运行；启动或睡眠恢复后同一自然日最多补跑一次。
- 自动化只支持一次性、每日和每周结构化计划，不接受原始 cron、任意 shell 或额外网络。交互式 Agent run 优先，到时运行持久排队并以自动化 ID + 计划时间防重。
- 每次确认模式把生成物写入停在持久化审批；低风险自动写入与 Bypass 可在“采办岛 Agent”目录新建不覆盖的产物。执行始终遵守当前全局权限。
- 每日清单严格生成 `DailyBriefingDocument`，包含逾期、今日、未来七日采购节点、合同履约事项和杂事，并保留实体来源；模型只可重排既有 ID 和提供有界建议。
- PDF 使用应用内固定 HTML 模板和 Electron `printToPDF`，原子写入 `采办岛 Agent/今日清单/YYYY/YYYY-MM-DD 今日工作清单.pdf`。无模型或分析失败时仍生成基础清单并显式标记。

### 通用规则

- 采购项目正式全名去除首尾空白后为 1–500 个字素，简称为 1–24 个字素；合同创建时两种名称至少一项非空，规范化后仍满足同样上限。杂事及节点名称遵循各自字段上限。时间存 ISO8601 UTC，按实体时区显示。
- 新设提醒不得在过去；节点截止不得早于开始；超出项目 deadline 时警告后再确认。
- 重命名、紧急度、节点开始时间与杂事提醒等局部写入携带预期旧值，冲突时拒绝覆盖。
- URL 仅允许 http/https；文件链接保存路径和元数据，不复制或读取文件正文。打开外部目标前展示完整目标并确认。
- Markdown 支持常用文本、列表、链接与代码；禁用原始 HTML、脚本、iframe 和远程嵌入。

## 4. 排序、编辑与生命周期

- 项目默认排序：紧急度 → 有 deadline 优先 → deadline → 创建时间 → ID。临时排序不跨重启。
- 杂事排序：已到时间 → 未来提醒 → 无提醒且最近更新 → ID。
- L2/L3 均可修改任务名、节点名、紧急度、节点状态与时间；失败保留用户输入并给出可重试原因。
- 节点、链接和任务永久删除需明确确认；支持撤销的 UI 删除延迟 5 秒提交。杂事工作单“完成”立即归档并反馈结果。
- 完成或取消任务会归档并取消对应提醒；恢复仅重建仍在未来的提醒。归档保留 SQLite 记录与 Markdown/JSON 快照，可搜索、查看和恢复。

## 5. Agent

- 唯一 Agent 运行时为 Pi Agent Core/AI `0.81.1`。DeepSeek 使用固定官方端点和 Flash/Pro 预设；GLM 只允许应用内列出的官方开放平台/Coding Plan 端点与模型；Peng 提供三个由用户显式选择且不得按模型名推断的入口：`/v1` OpenAI Chat Completions、`/v1` OpenAI Responses、根地址 Anthropic Messages。三个 Peng Provider 共用一个加密 Key、分别保存模型，模型目录由 Bearer `GET /v1/models` 获取并稳定排序。
- 全局同时只有一个 run；单次 provider 请求 120 秒超时并有限重试，run 最长 15 分钟，最多 12 轮。切换页面、收起和 renderer 重载不中止；显式取消、超时、上限或退出才终止。
- 会话、本地可见消息、脱敏工具状态和使用量可持久化、删除、清空及导出。Provider 返回的结构化思考流只在当前运行内临时显示：正式回答开始后自动收起为可展开的“思考过程”，不得写入 SQLite、日志、记忆、搜索或导出。不提供结构化思考流的企业模型只显示正文。完整工具结果、Key、Authorization 和敏感路径不得保存或显示。
- 事件带单调序号；renderer 先订阅再初始化，并在发送返回、终态、层级切换、重载和重新展开时用运行快照补偿。正文与思考增量按动画帧合并渲染；消息视口在首次进入、重新进入和流式增长时定位到最新内容。UI 区分连接、思考、正文流式、工具、等待批准、应用结果与失败。
- 工具覆盖任务、节点、提醒、备注、链接、归档/恢复/删除，以及授权目录内的列举、读取、写入、移动和单文件删除；无任意 shell、任意网络或未授权路径。
- 发给模型的每个工具参数必须是顶层 `type: object` 的 JSON Schema；可空 UTC 字段必须保留真正的 `null`，不得在 provider 转换阶段变为空字符串。
- 每轮只执行最新一条用户消息；历史消息只提供上下文，除非用户明确要求继续，否则不得重放历史中失败或未完成的请求。
- Agent 可读取合同列表与详情，并通过同一 AppCommand/权限链路维护台账、资料、合同节点和提醒。

| 权限模式 | 自动执行 | 仍需确认 |
| --- | --- | --- |
| 每次写入确认 | 查询、搜索、授权目录读取 | 所有正式数据与文件写入 |
| 低风险自动写入 | 字段、说明、紧急度、备注、提醒、节点/链接新增编辑、节点状态和排序 | 创建、归档/恢复、删除、记忆、文件写入/移动 |
| Bypass | 全部注册命令与授权目录文件操作 | 无；仍受命令、目录、safeStorage、回环及无 shell/网络边界约束 |

Bypass 跨重启保持，首次启用确认风险并始终显示警示。需确认调用以内联差异卡展示；批准后继续同一工具循环，拒绝或取消结果反馈给 Agent。

## 6. 提醒、归档与同步

- 项目 deadline 可配置多个提前量；采购节点、合同节点与杂事按精确时间准时提醒。未设置时间不调度。
- Windows Toast 点击后进入对应任务、采购节点、合同节点或杂事；通知不可用时使用不抢焦点的岛内提示。
- 启动或睡眠恢复时原子领取漏发提醒并合并摘要；提醒只能触发一次。
- 归档快照位于 `%APPDATA%\caiban-island\archive\YYYY-MM\...`，备份保留最近 7 份。
- 飞书 PersonalBaseToken 经 safeStorage 保存；只按采办岛任务 ID 幂等 upsert 活跃采购项目，合同、杂事与知识数据不外发，失败不影响本地数据。CSV/Markdown 导出始终可用。
- 飞书 Agent 机器人使用官方 Channel 长连接，不监听公网或新增本地端口；App Secret 经 safeStorage 保存。一次性 8 位配对码有效 10 分钟且仅私聊 `/bind` 可用，可配对多人并可撤销。私聊无需提及，群聊必须 `@机器人`；仅接收 text/post，不下载附件。
- 每个 `chat_id` 续接一个本地 Agent 会话；`/new` 只清空映射，另支持 `/status`、原发起人的 `/cancel` 与 `/help`。全局 Agent 忙碌时普通消息立即拒绝且不排队；桌面会话与飞书会话使用同一全局 run 与三档权限。
- 飞书进度卡只显示可见正文、工具阶段、审批摘要和终态，不发送思考增量、原始工具结果、凭据或敏感绝对路径。审批仅本次飞书 run 原发起人可操作；重复、跨用户或过期动作安全拒绝，桌面处理同一审批后同步更新卡片。

## 7. 安全与失败模式

- 各模型 Provider 的 API Key、飞书 App Secret、PersonalBaseToken 和本地命令令牌只经 safeStorage 加密保存，不进入明文数据库、renderer 返回值、日志、快照、备份、导出、测试或源码。模型测试只发送固定“仅回复 OK”，不得发送采购资料。
- 本地命令端点只绑定 `127.0.0.1`，校验令牌、Content-Type、体积和完整 AppCommand schema；CLI 不启动 shell。
- 授权文件路径由 main 执行规范化与 realpath 校验，拒绝 `..`、设备/UNC、符号链接或目录联接逃逸。
- 高对比度、减少动画或 Acrylic 失败时使用确定性纯色/direct 模式；GPU 不可用时降级但不得阻止操作。
- 数据损坏、断网、认证、限流、5xx、断流、空响应与超时均应安全失败并提供可操作反馈。

## 8. 当前验收基线

1. Win10/Win11 portable 可运行；L1 不遮挡，L2/L3 返回与全屏退让正确。
2. 0/1/7/100 数据、采购/合同/杂事三轨组合、长中文和逾期状态布局正确。
3. 项目、合同、合同节点、提醒、链接、备注、归档与恢复事务一致，金额精确且乐观并发冲突不覆盖。
4. L2 默认卡片；L2 Agent 为纯对话视图，L3 提供权限与会话管理，两层共享会话和运行状态，L3 无“AI 草稿”。
5. Agent 在隔离合成数据中可生成、修改、删除卡片并整理授权文件；未授权相邻目录不变。
6. 三档权限、批准/拒绝、Bypass 警示、事件丢失补偿和错误重试正确。
7. 键盘、读屏、44×44px 目标、WCAG AA、高对比度、减少动画与 100/125/150% DPI 通过。
8. 日志、SQLite、导出、包与测试夹具无真实凭据、reasoning 或私人路径。
9. Peng 三协议路径、鉴权与模型测试正确；飞书私聊/群聊、配对、忙碌拒绝、审批归属、断网重连、重启与撤销在合成数据中通过。
