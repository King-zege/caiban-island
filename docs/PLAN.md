## 2. 已锁定决策

- Electron + TypeScript + React + Zustand；SQLite 由 main 独占。
- 同一个窗口承载 L1/L2/L3；L2 默认任务卡片，Agent 按需切换。
- 项目和杂事是不同模型；节点开始时间与杂事时间是精确提醒。
- 合同是独立领域，可关联采购项目或单独录入；金额使用整数最小货币单位，生命周期与合同节点分离。
- Pi Agent 是唯一 Agent 运行时，可使用 DeepSeek、GLM 或 Peng 三个显式协议 Provider；正式写入统一经 AppCommand/AppService。
- Agent 权限为每次确认、低风险自动写入、Bypass；无任意 shell、额外网络工具或未授权文件访问。
- 本地回环 API + `caiban-cli` 只调用注册命令；飞书多维表格仅单向导出，飞书机器人是独立且受同一权限链约束的 Agent 通道。
- SQLite + Markdown/JSON 快照是正式本地存储；portable EXE 是推荐分发物。
- 每个新节点先同步规范和测试，通过门禁后按 `P{n}: ... — 测试与验收通过` 独立提交。

## 3. v0.4 完成状态

P30 在 v0.4 基线上完成 Peng 三协议与飞书远程 Agent 应用化接入；后续增强从新节点开始，不回写 P22–P30 的验收范围。

## 4. 新工作如何进入计划

新增行为先在本节登记一个新节点，至少写清：范围、非目标、公共契约/迁移、自动化、Windows 人工矩阵、完成标准和提交信息。不要回填或扩写已完成节点。

建议模板：

| 节点 | 范围 | 测试与人工验收 | 完成标准 |
| --- | --- | --- | --- |
| P{n} | 当前需求与明确非目标 | 受影响测试 + 全量门禁 + 必要 Windows 矩阵 | 可观察结果、兼容性、安全与打包均通过 |

## 5. 候选增强

- OCR、旧式 Office 正文提取和云端知识源（P25 第一版只索引这些格式的元数据）。
- 自定义排序、节点依赖/子节点、多显示器多岛、Arm64。
- 附件托管、数据库加密、导出密码保护。
- 飞书多维表格双向同步、附件下载或 OAuth 需重新评估数据主权和企业管理员权限，当前不在范围内。

## 6. 持续风险

| 风险 | 缓解 |
| --- | --- |
| Win10/GPU/Acrylic 差异 | pure fallback + software/direct；业务功能优先 |
| 本地端口被企业网络或杀软阻断 | GUI 不依赖 CLI；端口只回环并随机选择 |
| Bypass 误配置 | 首次确认、持续警示、命令与目录硬边界 |
| Electron 常驻成本 | 目标 <250MB，100 任务使用虚拟化与性能门禁 |
| 无签名 SmartScreen | README 明示，不尝试绕过 |
